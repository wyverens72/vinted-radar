# Локальный сервер Express / SQLite

В каталоге `server/` сохранена исходная однопользовательская версия. Она использует React-интерфейс, Express, SQLite и Telegram polling. Облачная версия приложения описана в [README](README.md) и [руководстве по развёртыванию](FREE_HOSTING.md).

Локальный сервер не поддерживает облачную регистрацию и отдельные аккаунты. Пароль предоставляет доступ к общему пространству поисков. Базы локальной и облачной версий не синхронизируются.

## Запуск

Требуется Node.js 24+.

```bash
npm ci
cp .env.example .env
```

Укажите в `.env` случайный `APP_PASSWORD` длиной не менее 16 символов. Для проверки без Telegram оставьте `BOT_TOKEN` и `TELEGRAM_OWNER_ID` пустыми и используйте демонстрационный источник.

```bash
npm run build
npm start
```

Откройте [localhost:3000](http://localhost:3000). Сервер и мониторинг работают только при запущенном процессе и включённом компьютере.

Настройки локальной версии перечислены в `.env.example`. Для разработки интерфейса доступны `npm run dev` и `npm run web`.

## Telegram

Для локального polling задайте `BOT_TOKEN` и числовой `TELEGRAM_OWNER_ID`, перезапустите сервер и отправьте боту `/start`. Используйте отдельного бота: активный облачный webhook несовместим с polling того же бота.

Для Mini App требуется публичный HTTPS-адрес в `PUBLIC_URL`. Локальный адрес подходит для браузерной проверки, но не для открытия Mini App из Telegram.

## Данные и размещение

SQLite хранится по пути `DATABASE_PATH`; значение по умолчанию — `./data/radar.sqlite`. Для резервного копирования используйте SQLite backup или копирование после корректной остановки сервера. Не публикуйте базу, `.env` и резервные копии.

`Dockerfile` и `compose.yaml` предназначены для самостоятельного размещения локального сервера. `render.paid.example.yaml` — пример платной конфигурации Render; он не используется рабочей облачной установкой. Для выбранной архитектуры с Workers и D1 используйте основное руководство.
