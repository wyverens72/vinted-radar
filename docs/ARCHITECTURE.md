# Архитектура

## Компоненты

Приложение состоит из веб-интерфейса, API, базы данных, сборщика каталога и Telegram-бота.

```text
Браузер / Telegram Mini App
           │
           ▼
    Cloudflare Worker ◄──── Telegram webhook
           │                        ▲
           ▼                        │
        D1 / SQLite           Telegram Bot API
           ▲                        ▲
           │                        │
   GitHub Actions           Cloudflare Cron
   сбор каталога            проверка поисков
                            и доставка очереди
```

Worker обслуживает интерфейс и API. D1 хранит аккаунты, сессии, поиски, находки, состояние просмотра каталога и очередь уведомлений. Сборщик работает отдельно от пользовательских запросов: открытие ленты не вызывает запрос к Vinted.

## Вход и аккаунты

При входе из браузера сервер создаёт запрос на пять минут. Кнопка открывает бота с параметром этого запроса. После нажатия «Запустить» проверенное сообщение из личного чата связывает запрос с Telegram-аккаунтом. В исходной вкладке пользователь видит имя и подтверждает вход. Код используется один раз; сессия хранится в защищённой HttpOnly cookie.

В Mini App проверяются подпись Telegram и срок действия `initData`. Переданный браузером Telegram ID сам по себе не даёт доступа. Пароль владельца предусмотрен как резервный способ входа.

Публичная регистрация управляется параметром `PUBLIC_REGISTRATION`. При её отключении новые участники регистрируются по одноразовым приглашениям. Отключённый аккаунт не восстанавливается командой `/start`.

## Поиски и фильтры

Новые поиски сохраняют каноническую ссылку каталога Vinted.pl. Сервер принимает только поддерживаемый адрес и параметры фильтров, исключает параметры страниц и отслеживания. Произвольные внешние адреса не загружаются.

Идентификаторы категорий, брендов, размеров и других фильтров передаются источнику. Выбранный порядок выдачи входит в ключ кэша и состояние просмотра каталога. При смене категории интерфейс сбрасывает размеры, относящиеся к предыдущей категории.

## Сбор каталога

В режиме `CATALOG_FETCH_MODE=github` сборщик запускается в GitHub Actions и получает до трёх различных активных запросов за запуск. Одинаковые ссылки используют общий кэш.

Для каждого запроса сборщик читает первую страницу и до четырёх более ранних страниц. Следующая позиция сохраняется в D1. Просмотр останавливается на пустой или повторяющейся странице либо на предельной глубине 10 000 страниц. После завершения проверяются первые две страницы. Неуспешный проход не продвигает позицию просмотра.

Импорт принимает до 500 объявлений за проход и проверяет идентификаторы, ссылки, валюту и адреса фотографий. Защищённый токен сборщика даёт доступ только к заданиям и импорту каталога, без доступа к пользовательским сессиям и настройкам бота.

При HTTP 401, 403, 429 или нераспознаваемой разметке устанавливается пауза не менее часа с учётом `Retry-After`. Сборщик не использует аккаунты Vinted, прокси и обход проверок. В режиме GitHub Worker не переключается на прямой сбор при ошибке.

## Находки и уведомления

Совпадения сохраняются отдельно для каждого поиска. Ключ «поиск + ID объявления» предотвращает повторную постановку одной находки в очередь. Первый проход также создаёт уведомления.

Очередь отдаёт приоритет находкам с первой страницы, затем отправляет более ранние результаты. За один запуск доставки обрабатывается до пяти карточек с распределением между чатами. Сообщения в один чат отправляются с паузой; при ограничении Telegram применяются повторные попытки с задержкой.

Если фотография недоступна для отправки, предусмотрено текстовое сообщение со ссылкой. Возможен редкий повтор, если Telegram принял сообщение, а сервер не успел сохранить подтверждение. Гарантия доставки «ровно один раз» не заявляется.

Веб-интерфейс сначала загружает последние 500 совпадений, затем позволяет запросить историю. Избранное и доступ к находкам проверяются по владельцу поиска.

## Хранение и доступ

- Поиски, избранное и уведомления изолированы по пользователю на уровне API.
- Владелец инфраструктуры технически имеет доступ к базе данных.
- `/stop` отключает уведомления и очищает ожидающую очередь пользователя, сохраняя поиски.
- Отключение участника завершает его сессии и блокирует доступ; данные поисков сохраняются.
- Отправленные записи очереди очищаются через семь дней. Сохранённые реальные находки автоматически не удаляются.
- Service worker не кэширует приватные ответы API. Для просмотра личных данных нужен интернет.

## Структура репозитория

| Путь | Назначение |
| --- | --- |
| `web/` | React-интерфейс, PWA и справочники фильтров |
| `cloudflare/` | API, авторизация, сбор, очередь и Telegram webhook |
| `migrations/` | Последовательные миграции D1 |
| `scripts/collect-catalog.js` | Сборщик для GitHub Actions |
| `.github/workflows/` | CI, сбор каталога и диагностика |
| `tests/` | Автоматические проверки |
| `server/` | Исходный локальный сервер и общие модули |

## Альтернативные источники

`DATA_SOURCE=demo` использует вымышленные объявления для локальной проверки. `authorized-feed` принимает отдельный импорт каталога через API владельца при включённом `AUTHORIZED_FEED_CONFIRMED`. Пример формата находится в `authorized-feed.example.json`. Эти режимы не требуют доступа к публичному каталогу Vinted.
