# Развёртывание

Рабочая конфигурация использует Cloudflare Workers для сайта и API, D1 для хранения данных и GitHub Actions для сбора каталога. Постоянно включённый локальный сервер не требуется.

Использование бесплатных тарифов зависит от действующих квот и типа ресурсов аккаунта. Перед созданием ресурсов проверьте условия [Cloudflare Workers](https://developers.cloudflare.com/workers/platform/pricing/), [D1](https://developers.cloudflare.com/d1/platform/pricing/) и [GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions). Не подключайте платные ресурсы, если требуется размещение без расходов.

## Подготовка

Требуются Node.js 24+, аккаунты Cloudflare и GitHub, а также Telegram-бот, созданный через [BotFather](https://t.me/BotFather).

```bash
npm ci
npm test
npm run build
npm run cloud:login
npx wrangler d1 create vinted-radar
```

Для собственной установки замените в `wrangler.jsonc`:

- `name` — имя Worker;
- `database_name` и `database_id` — имя и ID созданной базы;
- `PUBLIC_URL` — публичный HTTPS-адрес приложения без завершающего `/`;
- `BOT_USERNAME` — username бота без `@`.

Не используйте ID базы опубликованной установки для собственной копии.

## Настройки

| Параметр | Назначение |
| --- | --- |
| `PUBLIC_URL` | Адрес сайта и Telegram Mini App |
| `BOT_USERNAME` | Имя Telegram-бота |
| `PUBLIC_REGISTRATION` | `true` — регистрация через бота; `false` — по приглашениям |
| `DATA_SOURCE` | `demo`, `vinted-public` или `authorized-feed` |
| `CATALOG_FETCH_MODE` | `github` — отдельный сборщик и общий кэш |
| `AUTHORIZED_FEED_CONFIRMED` | Подтверждение для отдельного режима импорта |

Секреты задаются отдельно от исходного кода:

```bash
npx wrangler secret put APP_PASSWORD
npx wrangler secret put BOT_TOKEN
npx wrangler secret put TELEGRAM_OWNER_ID
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
npx wrangler secret put CATALOG_COLLECTOR_TOKEN
```

`APP_PASSWORD` — случайный пароль владельца длиной не менее 24 символов. `BOT_TOKEN` выдаёт BotFather. `TELEGRAM_OWNER_ID` — числовой ID владельца. Для `TELEGRAM_WEBHOOK_SECRET` и `CATALOG_COLLECTOR_TOKEN` используйте разные случайные значения; токен сборщика можно создать командой `openssl rand -hex 32`.

Для первого запуска без Telegram и сборщика достаточно пароля владельца и `DATA_SOURCE=demo`. Дополнительные секреты нужны при подключении соответствующих компонентов.

Не публикуйте `.env`, `.dev.vars`, локальные файлы секретов и резервные копии. Эти пути исключены через `.gitignore`.

## Публикация

```bash
npm run cloud:db:remote
npm run cloud:deploy
```

Если адрес Worker ещё неизвестен, начните с демонстрационного режима, получите адрес после первой публикации, задайте `PUBLIC_URL` и опубликуйте повторно.

Войдите по паролю владельца. В разделе «Подключение» раскройте «Управление приложением» и нажмите «Восстановить связь с ботом». Действие регистрирует webhook, команды и кнопку Mini App. Отправьте боту `/start` и проверьте уведомление из приложения.

Один бот должен использовать один способ получения обновлений: облачный webhook или локальный polling. Не запускайте обе версии с одним токеном одновременно.

## Сборщик GitHub Actions

1. Разместите исходники в собственном репозитории.
2. В `.github/workflows/collect-catalog.yml` замените `RADAR_URL` на адрес своей установки.
3. В настройках репозитория откройте **Secrets and variables → Actions** и добавьте `CATALOG_COLLECTOR_TOKEN`. Значение должно совпадать с секретом Worker.
4. Задайте `DATA_SOURCE=vinted-public` и `CATALOG_FETCH_MODE=github` в настройках Worker и опубликуйте изменения.
5. Создайте активный поиск. Запустите workflow **Collect public catalog** вручную через вкладку Actions и проверьте результат.

Workflow настроен на запуск примерно каждые пять минут. GitHub может задерживать запуски; точное расписание доставки не гарантируется. При нескольких запросах сборщик последовательно обрабатывает очередь. Проверяйте доступность расписания и квоты своего аккаунта GitHub.

## Регистрация участников

При `PUBLIC_REGISTRATION=true` участник открывает сайт, начинает вход через Telegram, нажимает «Запустить» в боте и возвращается в исходную вкладку для подтверждения аккаунта. При первом входе создаётся отдельный аккаунт и подключаются уведомления.

Владелец также может создать одноразовое приглашение на 24 часа, отозвать неиспользованное приглашение или отключить участника. Пароль владельца не предназначен для общего доступа.

## Обновления

```bash
npm ci
npm test
npm run cloud:db:remote
npm run cloud:deploy
```

Миграции применяются до публикации кода. Обычное обновление Worker не заменяет базу. Не удаляйте и не пересоздавайте заполненную D1 для обновления приложения.

Workflow **Check** проверяет код при push и pull request, но не публикует Worker автоматически.

## Резервное копирование

```bash
npx wrangler d1 export DB --remote --output=./backups/cloudflare.sql
```

Резервная копия содержит пользовательские данные и сведения о сессиях. Храните её в защищённом месте вне публичного репозитория. Восстановление сначала проверяйте в отдельной базе.

## Диагностика

| Проблема | Проверка |
| --- | --- |
| Бот не отвечает | Токен, webhook, настройки владельца; затем повторный `/start` |
| Вход не завершается | «Запустить» в боте, возврат в исходную вкладку, срок действия запроса — пять минут |
| Лента не обновляется | Активность поиска, последний запуск Actions, статус источника в приложении |
| Уведомления задерживаются | Ожидающая очередь, состояние Telegram, включённые уведомления |
| После обновления ошибка базы | Применены ли все миграции к правильной базе |
| Ошибка соединения | Доступность сайта и сети; повторная загрузка страницы |

Владелец может использовать `/api/admin/catalog/diagnostic` для просмотра сохранённой диагностики источника. Получение диагностики не запускает новый запрос к Vinted.
