# Проверка приложения

## Автоматические проверки

```bash
npm test
npm run build
npm run cloud:check
```

`npm test` запускает модульные и интеграционные тесты через Node.js Test Runner. Для проверки D1 используется адаптер на настоящей SQLite с применением миграций. `npm run build` собирает интерфейс, `npm run cloud:check` проверяет сборку Worker без публикации.

Эти команды также выполняются в GitHub Actions при push и pull request. Тесты не используют настоящие Telegram-токены и не отправляют сообщения пользователям.

## Покрываемые сценарии

| Область | Проверки |
| --- | --- |
| Авторизация | Подпись и срок действия Telegram `initData`, доступ владельца, отказ посторонним запросам |
| Вход из браузера | Ожидание подтверждения в Telegram, привязка к аккаунту, однократное использование, истечение срока, запрет повторной привязки |
| Участники | Регистрация, лимиты, приглашения, отзыв и отключение доступа |
| Изоляция данных | Доступ только к собственным поискам, находкам и избранному |
| Фильтры | Допустимые URL и параметры, точные ID, сортировка, отклонение внешних адресов |
| Каталог | Разбор карточек, фото и цен, проверка импортируемых записей, ограничения сетевых запросов |
| Просмотр страниц | Возобновление просмотра, удаление повторов, остановка и сохранение позиции при ошибках |
| Уведомления | Первый проход, дедупликация, приоритет первой страницы, повторная доставка и ограничения Telegram |
| История | Загрузка более ранних результатов с устойчивой сортировкой и изоляцией по пользователю |

## Ручная проверка перед выпуском

1. Зарегистрировать тестовый аккаунт через бота и войти в исходной вкладке браузера.
2. Открыть Mini App и проверить доступ к тому же аккаунту.
3. Создать поиск вручную и по ссылке; проверить сохранение фильтров после перезагрузки.
4. Проверить ленту, избранное, историю, изменение и приостановку поиска.
5. Получить карточку в Telegram и открыть исходное объявление.
6. Убедиться, что другой аккаунт не видит эти поиски и находки.
7. Проверить узкий экран, клавиатурную навигацию и установку PWA в поддерживаемом браузере.
8. Проверить запуск фонового сборщика и статус очереди без открытой вкладки.

Для ручных проверок используйте отдельного тестового бота и тестовую установку, если сценарий изменяет данные или отправляет сообщения.

## Границы проверки

Автоматические тесты проверяют поведение приложения на сохранённых примерах и контролируемых ответах внешних сервисов. Они не подтверждают постоянную доступность Vinted, фактическое расписание GitHub Actions или доставку Telegram на каждом устройстве.

Изменение разметки Vinted требует проверки парсера на новых публичных примерах. Работа в отдельных браузерах и установка PWA проверяются на соответствующих устройствах. В проекте нет измеренного SLA и гарантии полного покрытия каталога.
